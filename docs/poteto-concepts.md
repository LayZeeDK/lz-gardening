# Lauren Tan's concepts and lz-gardening

Barnaby Robson's [On pstack](https://barnabyrobson.org/on-pstack/) collects Lauren "poteto" Tan's ideas about
building with agents. This page goes through each one and records whether lz-gardening uses it, how, or why not.
Quotes are Lauren's, from her posts and her interview with Matt Pocock
([MN9dGgmLyso](https://www.youtube.com/watch?v=MN9dGgmLyso)).

## The Gardener (the plugin's core)

| Concept                                                                                                                              | In lz-gardening                                                                                                                                                                                                               |
| ------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Watch**: an agent scans for bad patterns all the time                                                                              | The `garden` tick, run by `/loop`. A census counts textual weeds; reading the diffs finds the rest.                                                                                                                           |
| **Queue**: "I don't actually tell it to fix the issue first. I tell it to append it to a document."                                  | `.garden/weeds.jsonl`, append-only, deduplicated by class, place and source. The tick never fixes.                                                                                                                            |
| **Group**: "every couple of days I look at it and I see actually these are all the same thing"                                       | `weeds.ts groups`; a class with two or more open weeds is reported `ready to tend`. Grouping by root cause is the tend pass's step 2.                                                                                         |
| **Sample** merged pull requests daily                                                                                                | The tick reads the newest 30 commits since the last tick and says how many it skipped. Lauren samples because one person cannot read everything; the gardener can read more, but the cap keeps a tick cheap after a long gap. |
| **Change the bed** when "multiple agents are having the same issue"; "if it was a one-off incident, it's fine"                       | The `lz-tend` skill, triggered by a class reaching two open weeds. One-offs are closed as such. The glossary uses **bed** for the tend pass's worktree, so the plugin says "turn the weed into a check" for this step.        |
| "every weed you pull becomes a rule, so it can't grow back"                                                                          | Tend writes the check first, proves it fails on a real weed, then clears the instances. A weed that comes back is marked `regrown`, which shows the check did not hold.                                                       |
| "the third isRecord this week"                                                                                                       | The census's duplicate-definition count and the `duplicate-helper` class.                                                                                                                                                     |
| "the lint suppressions creeping like ivy"                                                                                            | Census patterns for every kind of suppression; a rising count shows up as `grew` in the tick summary.                                                                                                                         |
| **Correction order** (16 August): architecture, then lint or test, then skill or rule, then a human reading diffs ("ngmi")           | The six layers in `weeds.md`, used by tend to choose where a fix goes.                                                                                                                                                        |
| **Organic architecture**: "the best rules are in your code"; hard constraints so "even the dumbest agent (and pilot)" can contribute | Why tend prefers layers 1 and 2, and why a check's message must name the fix. It is also why angular-ai-devtools, built mostly on smaller models, is the proving ground.                                                      |
| **Bonsai**: commits grow where they please; constraints tame them                                                                    | The same idea as the layers; no separate mechanism.                                                                                                                                                                           |
| **Encode lessons in structure**: the second time you write an instruction, put it in the code                                        | The `rule-in-prose` and `repeated-lesson` classes.                                                                                                                                                                            |

## The Michelin kitchen

| Concept                                                                                                                    | In lz-gardening                                                                                                                    |
| -------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **Tasting**: "you cannot be tasting every single dish"; when the same fault shows up in several dishes, change the kitchen | The tick (sampling) and the tend pass (changing the kitchen). The plugin README uses the image.                                    |
| **Kitchen layout and prep**: the codebase, types and lint rules put each cook on a narrow path                             | What a tend pass builds.                                                                                                           |
| **Knives**: skills, small CLIs, verification tools                                                                         | `census.ts` and `weeds.ts` are the gardener's knives: deterministic, tested, run the same way each tick.                           |
| **Home cook, family, head chef, restaurant group**                                                                         | Not used directly. The plugin is for the head chef and restaurant group stages, where agents run without a human at every station. |
| **Executive chef** (a coordinator agent)                                                                                   | Not built. One gardener per repository; a coordinator across repositories is out of scope.                                         |
| **The chef's own knives** (each engineer's own skills)                                                                     | Respected: the plugin names none of its maintainer's own skills, so anyone can install it beside their own.                        |
| **Volume**: worth it only once the kitchen holds                                                                           | The reason to garden: the more agents land, the faster weeds spread.                                                               |

## The Trust Ladder

| Concept                                                                                    | In lz-gardening                                                                                                                         |
| ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| Trust grows with tools that let agents prove their work                                    | `missing-check` queues a kind of check the repository lacks; each check a tend pass adds is one more thing agents can prove.            |
| **Caution: stuck low**, too busy micromanaging to sharpen knives                           | The gardener does the noticing so a human only reads `ready to tend` lines.                                                             |
| **Caution: verifiability**                                                                 | `stale-verification` and `claim-as-evidence` classes watch whether the repository's own verification keeps up.                          |
| **Autopilot**: agents merge their own work and she reads the commit history in the morning | The tick is that morning read, done by an agent, and leaves its notes in the queue. Merging stays human: nothing in the site is pushed. |

## Inner and outer loops

| Concept                                                                           | In lz-gardening                                                                                                                                                                     |
| --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Outer loop** watches channels and routes work                                   | Not used. The gardener's only input is the repository: its commits, census and records. Bug reports are not weeds.                                                                  |
| **The join**: related reports go to one project so the shared cause is fixed once | The same instinct as grouping: weeds of one class go to one tend pass.                                                                                                              |
| **Where am I the bottleneck?**                                                    | The tick's report is short so the human reads it in seconds.                                                                                                                        |
| **First mile, last mile, Sandcastle, Benny**                                      | Not used. From Benny the gardener borrows "fail closed when missing or uncertain" (a failed step stops the tick) and duplicate checks before creating anything (the queue dedupes). |

## Hands, eyes and a map

| Concept                                                                                                                                      | In lz-gardening                                                                                                                                                                                 |
| -------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Verification skill, small CLI, Feature Map**                                                                                               | Not built here; a repository's own verification is a separate job. The gardener queues `stale-verification` when a change to features does not update them, and leaves the refresh to that job. |
| **A stack the agent can see**                                                                                                                | Not used.                                                                                                                                                                                       |
| **Cloud agents**                                                                                                                             | Not used. The site is a local clone, which keeps the gardener off the machine's other checkouts.                                                                                                |
| **Dr Eggbot's healthchecks**: "Both stay quiet when there is nothing to propose. Do not create anything from a report until the user picks." | The one-line quiet tick, and propose-only for layer 3 guards.                                                                                                                                   |

## Measure a hundred times, cut once

| Concept                                                                           | In lz-gardening                                                                                                                     |
| --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| **Restate in your own words**                                                     | Tend step 2: the root cause in two sentences before choosing a check.                                                               |
| **README first**                                                                  | The plugin README and glossary were written before the first practice run.                                                          |
| **Prototype, /architect**                                                         | Used to build the plugin itself (an arena of independent rebuilds of the scripts), not by the plugin.                               |
| **Multi-phase plan with proof per task**                                          | Each skill step ends on a check.                                                                                                    |
| **Shorten the skill**: delete exact commands as models improve, keep the workflow | The skills keep commands only where a mistake would cost (the census and queue commands, the site setup); judgement stays in prose. |

## pstack skills that overlap

These are the maintainer's own tools; the plugin does not depend on them.

| Skill                          | Relation                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/correct`                     | The closest relative. It turns a repeated mistake into the strongest check, and proves the check fails on a real past mistake. `tend` does the same for one weed class, fed by the queue instead of a conversation. Its rules "a class counts once it has happened twice" and "if the pattern is already common, fail only when a change adds more" are the `ready to tend` threshold and the baseline that only shrinks. |
| `/reflect`                     | Mines one transcript for lessons and routes them to skill edits. The gardener mines the repository instead of transcripts, and routes to checks rather than skill text.                                                                                                                                                                                                                                                   |
| `/recall`                      | Loads past transcripts for context. Not used: the gardener's memory is the queue and the census.                                                                                                                                                                                                                                                                                                                          |
| `/automate-me`                 | Builds a personal working-style skill. Not used: the plugin encodes a codebase's rules, not a person's style.                                                                                                                                                                                                                                                                                                             |
| `/deslop`, `/no-comments`      | Their categories (comments a human would not write, unneeded defensive checks, casts to get around types, style drift) became read classes in `weeds.md`: `narrating-comment`, `defensive-noise`, `double-cast`, `style-drift`.                                                                                                                                                                                           |
| `/maintain-verification-skill` | Kept separate: the gardener only queues `stale-verification`.                                                                                                                                                                                                                                                                                                                                                             |
